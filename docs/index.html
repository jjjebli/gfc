Stop paying for files your model already read.

gfc — git-for-context. The transcript is a linear replay: every turn re-sends content the model has already seen. gfc treats it like git treats a working tree — the model gets a diff against what it last saw, never a full re-checkout. Unchanged re-reads collapse to hash-verified stubs. Changed files return just the hunk. Zero per-turn overhead, zero dependencies.

The transcript is a linear replay.

·

Re-reads re-pay

The only way a model "knows" a file at turn 40 is the file being literally present in the transcript at turn 40. Same 500-line file read ten times? Ten copies. Every one billed, every one diluting attention.

·

Caching cuts cost, not tokens

Provider prompt caches reduce the price of re-sent context — the tokens still flow, still compete for attention, and the cache shatters the moment history changes mid-prefix.

·

Summarization is lossy

Compaction throws away hard-won detail, and the model re-derives what was lost. Waste plus repeated work.

+

gfc: exact, not approximate

Not compression — deduplication. A sha256 says the bytes are identical, so the duplicate never enters the transcript at all. Nothing is summarized away; the content is verifiably still in context from the first read.

How it works.

One registry, one invariant: the filesystem is the store of truth. If on-disk content still hashes to the registered value, it is byte-identical to what the model already saw.

i.

Hash every full read

sha256 of file content, recorded per session in ~/.gfc/registry.json. Registry writes are atomic and cross-process locked — parallel sessions can't corrupt each other.

ii.

Intercept before the transcript

OpenCode plugin hooks tool.execute.after and replaces repeat content before it enters the message history. The duplicate never exists.

iii.

Return the delta

Unchanged → a ~45-token stub citing the hash. Changed → a unified diff of last-seen → current. Slice reads always pass through, with a note if the file drifted.

iv.

Scope to the session

Models are stateless: the first full read in any session is always real content. No stub can ever hide something the model hasn't seen. Compaction receives the verified-file list so summaries stay lean.

Known ceilings.

Stated up front, because a token-saving tool that oversells is a token-wasting tool.

  • Diffs are single-hunk. Scattered edits fall back to full content when the diff would be larger. Myers upgrade only when that measurably hurts.
  • Files >512KB are never diffed — full re-read on change. Binary files are rejected outright by the MCP tool.
  • The OpenCode hook relies on tool.execute.after output mutation, verified on opencode 1.18.29. If a future version stops persisting it, the fallback is experimental.chat.messages.transform as a send-time rewriter.
  • No savings without re-reads. If your model reads a file once and never looks back, gfc does nothing — by design, it costs nothing too.
