Stop paying for files your model already read.

GFC is an OpenCode plugin and MCP server. It treats the transcript the way git treats a working tree: the model gets a diff against what it last saw, never a full re-checkout.

The transcript is a linear replay.

Every turn re-sends the whole history. Here is what the usual fixes change, and what they don’t.

Re-reads re-pay.

The only way a model knows a file at turn 40 is that the file is literally present in the transcript at turn 40. Read a 500-line file ten times and you get ten copies, each billed and each diluting attention.

Caching cuts cost, not tokens.

Provider prompt caches lower the price of re-sent context. The tokens still flow, still compete for attention, and the cache breaks as soon as history changes mid-prefix.

Summarization is lossy.

Compaction throws away detail, and the model re-derives what was lost. That is waste plus repeated work.

GFC: exact, not approximate.

Not compression, but deduplication. A sha256 proves the bytes are identical, so the duplicate never enters the transcript at all. Nothing is summarized away. The content is verifiably still in context from the first read.

How it works.

One registry, one invariant. The filesystem is the store of truth. If the content on disk still hashes to the registered value, it is byte-identical to what the model already saw.

Hash every full read.

sha256 of file content, recorded per session in ~/.gfc/registry.json. Registry writes are atomic and cross-process locked, so parallel sessions can’t corrupt each other.

Intercept before the transcript.

The OpenCode plugin hooks tool.execute.after and replaces repeat content before it enters the message history. The duplicate never exists.

Return the delta.

Unchanged gives a ~45-token stub that cites the hash. Changed gives a unified diff from last-seen to current. Slice reads always pass through, with a note if the file has drifted.

Scope to the session.

Models are stateless, so the first full read in any session is always real content. No stub can hide something the model hasn’t seen. Compaction receives the verified-file list, so summaries stay lean.

Install in two commands.

Two integration paths. The plugin is enforced. The MCP server is advisory.

OpenCode plugin

Hard interception. Hooks the read tool. Automatic, invisible, enforced.

git clone https://github.com/jjjebli/gfc ~/.gfc
cp ~/.gfc/gfc-plugin.ts ~/.config/opencode/plugins/gfc.ts

Then restart OpenCode. There is nothing else to configure. You’ll see [GFC] stubs where duplicates used to be. Symlink the plugin instead of copying it, and git pull becomes your update path.

MCP server

Advisory. Adds a gfc_read tool that your agent is instructed to prefer.

# ~/.codex/config.toml
[mcp_servers.gfc]
command = "node"
args = ["/Users/you/.GFC/mcp.mjs"]

In interactive Codex, approve gfc_read once and always allow it. For codex exec, add --approve-for-me. A recommended rule for ~/.codex/AGENTS.md: prefer gfc_read over cat, head, sed, and tail.

Knobs.

Two environment variables, one reset, and a test suite that runs without an LLM or network access.

GFC_HOME=/dir
Relocates all state. Useful for isolating benchmarks or parallel installs.
GFC_DEBUG=1
Traces every hook decision to ~/.gfc/debug.log.
rm -rf ~/.gfc
Full reset. Rebuilds itself on the next read and costs one full read per file. It’s a cache, so treat it like one.
Tests
GFC_HOME=$(mktemp -d) node ~/.gfc/core.mjs and node ~/.gfc/test.mjs. Deterministic, with no LLM and no network.

Known ceilings.

Stated up front, because a token-saving tool that oversells is a token-wasting tool. Open any of them for the details.

−Diffs are single-hunk.

Scattered edits fall back to full content when the diff would be larger. A Myers upgrade happens only when that measurably hurts.

−Files over 512 KB are never diffed.

They get a full re-read on change. Binary files are rejected outright by the MCP tool.

−The OpenCode hook depends on output mutation.

It relies on tool.execute.after output mutation, verified on opencode 1.18.29. If a future version stops persisting it, the fallback is experimental.chat.messages.transform as a send-time rewriter.

−No savings without re-reads.

If your model reads a file once and never looks back, GFC does nothing. By design, it costs nothing too.
